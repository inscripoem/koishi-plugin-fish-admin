## 前置步骤

1. 在 Koishi 控制台的「插件配置」里添加并启用 `adapter-onebot`，填写连接信息（反向 WS / 正向 WS / HTTP 任选其一）。
2. 确认管理器 bot 已登录，并且已经在目标群里。
3. 把管理器设为目标群的**管理员**。没有管理员权限，撤回他人消息和禁言都会失败。
4. 让一只测试用“大肥鱼”也在目标群里，并能正常发言。
5. 启动开发模式：

```bash
cd /home/inscripoem/dev/koishi-workspace
yarn dev
```

6. 在 Koishi 控制台确认 `fish-admin` 插件已加载。如果配置页没有出现，先在 `koishi.yml` 的 `plugins` 下添加：

```yaml
fish-admin:
```

## 验证步骤

### A. 列群

在私聊或目标群里执行：

```
fish.groups
```

预期：输出管理器所在群的 ID、群名、平台与 bot 账号。把目标群 ID 记下来。

### B. 基础自检

在目标群里执行：

```
fish.preflight
```

预期输出：

- 群 ID / 群名
- 平台
- 管理器 QQ
- 数据库可用
- 管理器角色（`owner` / `admin` / `member`）

如果角色不是 `admin` 或 `owner`，先修权限，不要继续。

### C. 收到鱼消息

让测试鱼在目标群发一条普通消息，然后在群里执行：

```
fish.preflight --test <测试鱼QQ>
```

预期：

- 能找到该 QQ 最近一条消息的 `messageId`；
- 撤回成功；
- 禁言 60 秒成功；
- 自动解除禁言成功。

如果提示“还没看到 QQ 在群里的消息”，说明管理器没有收到该鱼的消息，或者消息缓冲还没建立；先确认 OneBot 是否上报其他 bot 的消息。

## 失败时的降级

| 失败项 | 处理 |
|---|---|
| 收不到鱼的群消息 | 插件只能做人工报表；检查 OneBot 是否过滤 bot 消息 |
| 能收到但不能撤回 | 保留禁言/踢出；撤回降级为记录 `recall_failed` |
| 能收到但不能禁言 | 保留撤回 + 记分；通知管理员频道；不自动踢 |
| 管理器不是管理员 | 强制 `dry-run`，先解决群权限 |
| 私聊发不出去 | 用管理员群，或只写日志；你个人不需要管理员群 |
